# 木叶手帖 · Naruto Journey

一个由 CSV 表格驱动的《火影忍者》观剧档案。支持按集数、人物、关系网、地域与故事线浏览。日常更新只需要编辑 CSV，不需要修改 HTML，也不需要构建工具。

## 网站功能

- 1–720 连续编号，分组为 1–99、100–199、200–299，以此类推；正文只显示当前分组，其他分组可在右侧悬停展开栏切换，手机点击打开。1–220 是初代；221–720 对应疾风传 1–500。
- 当前预填前 10 集；其余为待填写空位，不会假装已有完整剧情。
- 人物卡片按立场显示绿、红、金三种底色，保留文字标签。
- 人物档案支持姓名／身份／关系搜索，以及立场、主线／支线、地域筛选。
- 人物列表使用紧凑文字卡片；点击后在详情中查看照片。详情支持 Part I、Part II、New Era 切换，只显示已填写图片的时期选项，加载失败的选项会隐藏。
- 分集人物可以按地域分组或筛选。
- 关系网支持拖动画布、拖动人物、滚轮和双指缩放、按钮缩放、适应画面与关闭关系文字。键盘聚焦节点后按 Enter 可打开详情，方向键可移动画布。
- 关系笔记另有独立的姓名／身份／关系搜索、立场、戏份、地域及截止集数筛选，不会改变上方关系网。关系网按截止集数显示人物和关系；筛选后仅保留符合条件的人物及它们之间的关系，孤立节点仍保留。
- 地域里的姓名按钮可以进入对应人物档案。
- CSV 数据管理页可下载、查看、导入预览，并检查基本数据错误。

## 文件结构

```text
naruto-journey/
├── index.html
├── styles.css
├── app.js
├── data-snapshot.js          # 仅供双击 HTML 时显示初始快照
├── .nojekyll
├── README.md
└── data/
    ├── characters.csv       # 人物，每人一行
    ├── episodes.csv         # 集数，每集一行
    ├── appearances.csv      # 每集每位人物一行
    ├── relationships.csv    # 每条关系一行
    └── stories.csv          # 每条故事线一行
```

## 第一次上传到 GitHub Pages

1. 将上面这些文件和 `data` 文件夹放到仓库根目录。不要额外套一层 `naruto-journey` 文件夹。
2. GitHub 仓库打开 **Settings → Pages**。
3. Source 选 **Deploy from a branch**；Branch 选 **main**；Folder 选 **/ (root)**；点击 Save。
4. Custom domain 留空。
5. 在 Actions 页面等待 **pages build and deployment** 成功。
6. 打开 https://heidiyf.github.io/naruto-journey/ 。

GitHub Free 使用 Pages 时，仓库需要公开。现有网站不用创建新仓库，直接更新原来的文件即可。

## 以后每次如何更新（不用修改 HTML）

1. 在网站的 **CSV 数据管理** 页面下载要修改的 CSV，或从 GitHub 的 `data` 文件夹下载当前版本。
2. 用 Excel、Numbers 或其他表格软件编辑。
3. 导出为 **CSV UTF-8（逗号分隔）**，保持文件名和第一行列名不变。
4. 可先在网站的 CSV 数据管理页选择本地 CSV，检查错误并预览。新增人物涉及多个文件时，一次选择相关文件。
5. 打开 GitHub 仓库的 **data** 文件夹，点击 **Add file → Upload files**。
6. 将修改后的同名 CSV 拖进去，点击 **Commit changes**，提交到 `main`。
7. 等待 Actions 中的 Pages 发布成功；刷新原来的网站网址。

**网站每次载入都会读取 `data/*.csv`。修改已发布的 CSV 后，不需要更新 `index.html` 或 `data-snapshot.js`。已经打开的网站需要刷新才能看到新数据。**

仅保存电脑上的 CSV 不会更新朋友看到的网站。网页导入是当前页面的预览，不写入 GitHub、不持久保存；刷新后会恢复线上数据。GitHub 一次上传多个相关 CSV，可以避免发布人物表和出场表暂时不一致的版本。

## 先看这几个例子

### 只添加已有人物的新出场

在 `appearances.csv` 增加一行：

| 集数 | 人物 | 地域 | 立场 | 本集备注 |
|---|---|---|---|---|
| 11 | 漩涡鸣人 | 木叶村 | 正派 | 爬树修行 |

这里“地域”是人物的地域归类／所属，不等同于本集所在地点。鸣人在波之国执行任务，仍可以归为木叶村。

### 添加一个新人物

1. 在 `characters.csv` 增加该人物，至少填写：人物、首次集数、地域、立场、戏份、身份、介绍。
2. 在 `appearances.csv` 添加此人的出场行，姓名必须完全相同。
3. 需要显示关系时，在 `relationships.csv` 填写人物一、人物二、关系和起始集数。
4. 把相关文件一起上传。网站默认截止到“已整理”的最大集数；如果新人首次集数更晚，需继续整理分集，或在筛选里提高截止集数。

### 补充第 11 集

`episodes.csv` 已有第 11 集那一行，不用再新增同集数行。填写实际标题、日文原题（可选）、简单剧情、关系变化，并把“已整理”改为“是”。再在出场表补充本集人物。

## 每张表的字段

### characters.csv · 人物表

| 列名 | 如何填写 |
|---|---|
| 人物 | 唯一姓名，其他表也使用这个姓名；改名需同步修改所有引用 |
| 首次集数 | 1–720 的整数，疾风传使用连续编号 |
| 地域 | 所属／出身归类，如木叶村、波之国、待确认 |
| 当前活动地 | 当前所在地点，可留空 |
| 立场 | 正派、反派、立场复杂/TBD（也接受“立场复杂”） |
| 戏份 | 主线 或 支线，不需要写 emoji |
| 身份 | 卡片上的短介绍 |
| 介绍 | 人物详情中的简单介绍 |
| 关系关键词 | 用于搜索，可以写同伴、老师、亲属姓名等 |
| 照片_Part1 | Part I 图片网址，或 `images/文件名.jpg` |
| 照片_Part2 | Part II 图片网址；没有独立版本可留空 |
| 照片_NewEra | 新时代图片网址；没有则留空 |
| 资料来源 | 来源页面网址 |

照片要填**图片本身的网址**，不能只填 Fandom 的人物页面网址。外部图片有可能失效；可用自己有权使用的图片，上传到仓库的 `images` 文件夹后填写相对路径。切换后续时期外观可能剧透。伊鲁卡、卡卡西在来源页的 Parts I–II 使用同一张图片，因此这两个字段可相同。

### episodes.csv · 分集表

| 列名 | 如何填写 |
|---|---|
| 集数 | 唯一的连续编号，1–720 |
| 系列 | 火影忍者 或 火影忍者疾风传 |
| 系列集数 | 对应系列自己的集数，如连续 221 对应疾风传 1 |
| 实际标题 | 显示在页面的大标题，可填你观看平台上的准确标题 |
| 日文原题 | 原版标题，用于核对，可留空 |
| 简单剧情 | 两三句易懂的话，描述这一集发生的事 |
| 关系变化 | 用完整句子说明关系，不需要写箭头 |
| 故事线 | 这一集属于哪条故事线 |
| 已整理 | 是 或 否；默认显示最新的已整理集数 |
| 标题来源 | 标题核对页面 |

中文标题在不同字幕与平台中可能不同。当前提供常见中文译名和前十集日文原题；“认可与毕业”等主题概括已移出标题位置。请按你使用的平台修改“实际标题”，而非把主题概括当成正式片名。

### appearances.csv · 出场表

| 列名 | 如何填写 |
|---|---|
| 集数 | 对应分集表的集数 |
| 人物 | 与人物表姓名完全一致 |
| 地域 | 本集采用的地域归类；留空时使用人物表 |
| 立场 | 本集立场；留空时使用人物表 |
| 本集备注 | 如重点人物、背景登场、回忆等 |

每人每集只写一行。人物档案和关系网按截止集数之前最新的出场记录确定立场与地域；没有出场覆盖时使用人物表。当前活动地仍使用人物表，尚未做逐集地点历史。

### relationships.csv · 关系表

| 列名 | 如何填写 |
|---|---|
| 起始集数 | 从哪一集起显示这条关系 |
| 结束集数 | 可留空；填入后仅在该集及之前显示 |
| 人物一 / 人物二 | 两个已登记的人物姓名 |
| 关系 | 如“老师与学生”“雇主与受雇者” |
| 简单说明 | 用一句话说明谁做了什么；单向好感、雇佣等方向靠文字表达 |

同一对人物可以有多条关系。若关系随剧情变化，可给旧记录填写结束集数，再新增一条新记录。关系图不用箭头，单向关系请在“关系”或说明中写明行动方。关系笔记可点击双方姓名查看详情。

### stories.csv · 故事线表

填写故事线、起始集数、结束集数（可空）、类型、状态、简单介绍。故事线页面显示截至最新已整理集数已开始的故事。它不是动画原创／漫画改编的分类。

## 本地预览

直接双击 `index.html` 可以查看下载包的初始快照。浏览器通常不允许本地 HTML 直接读取旁边的 CSV，所以修改本地 CSV 后，请在“CSV 数据管理”中导入预览。

也可以在网站文件夹启动本地 HTTP 服务：

```sh
python3 -m http.server 8000
```

然后打开 http://localhost:8000/ 。HTTP 模式与 GitHub Pages 一样，直接读取 CSV。

## 资料范围与来源

- 当前人物介绍与剧情笔记以第 10 集为范围，不代表角色最终立场。
- 截止集数筛选控制人物是否出现、出场立场／地域、关系起止；人物介绍仍是人物表当前版本，并非每一集的历史快照。
- [NARUTO 官方动画目录](https://naruto-official.com/en/anime/naruto1/list)
- [前十集原题核对](https://cal.syoboi.jp/tid/210/subtitle)
- [Narutopedia 人物目录](https://naruto.fandom.com/wiki/Category:Characters)
- 部分图片路径参考公开的 [Naruto 图片索引](https://github.com/muhammadpauzi/naruto-api/blob/main/data.json)，图片实际由 Narutopedia CDN 提供；人物表保留各自资料页链接。
- 外部资料可能包含剧透。作品名称、角色、设定与图片的权利归原权利人所有；本项目为非官方观剧记录。

## 一键上传到 GitHub

已附 `同步到GitHub.command`。先按 `GitHub同步设置.md` 用 GitHub Desktop 克隆仓库，再把脚本与网站文件放到克隆文件夹根目录。以后双击脚本，会提交网站文件并推送到 main，之后等待 GitHub Pages 发布。它使用本机 Git 的现有凭据；不会在保存文件时后台自动执行。尚未配置或认证失败时，也可以在 GitHub Desktop 中 Commit 后点击 Push origin。

## 忍术与持续观剧记录

新增 `data/jutsu.csv`：人物、忍术、首次展示集数、类型、备注、资料来源。同一人物的同一招式只保留首次展示记录。所有人物卡片显示截至所选集数已经展示的招式；未确认的能力不推测填写。人物档案每次进入默认最新已整理集数，也可以手动回看更早资料。

可以直接在同一个聊天里报告新看的一集、谁出场和发生了什么，助手按 `观剧维护约定.md` 补表、确认疑点、去重并更新仓库。数据检查区也可下载、导入和预览忍术表。
